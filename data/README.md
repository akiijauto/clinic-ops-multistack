# data/ — 5実装が共通で使う合成データ

**すべて架空のデータ。** 実在の動物病院・飼主・動物・獣医師・薬品名・保険会社名・
料金表の値は1件も含まない。住所・電話番号も明らかに架空と分かる形にしてある
（`はるかぜ県こだま市` のような実在しない地名、`03-0000-xxxx` のような実在しない番号帯）。

形は `spec/model.md` に従う。**画面から編集しない**（`spec/README.md`）。
各実装はこのディレクトリのJSONを読み込んで初期データを作ること。

## ファイル一覧

| ファイル | 中身 | 件数 |
| --- | --- | --- |
| `lab_items.json` | 検査項目と基準値。`species`（dog/cat/other）と `sex`（male/female/any）で範囲が変わる | 30項目 |
| `price_items.json` | 料金項目。`price_code` / 名称 / 単価 / 課税区分 / 2階層の分類 | 120項目（**うち単価未設定 8件**） |
| `masters.json` | 予防の種別・受付の種別・診療科・定型文・料金分類の一覧 | — |
| `seed.json` | 病院・スタッフ・飼主・動物・受付・診察・経過記録・予防・投薬・検査・会計・予約・入院の初期データ | 下表参照 |
| `make_data.py` | 上記4ファイルを生成するスクリプト（標準ライブラリのみ） | — |

## 生成し直す手順

```bash
cd data
python make_data.py
```

- 乱数の種は `SEED = 20260905`（スクリプト冒頭）で固定。**同じスクリプトを2回流すと、
  4つのJSONはバイト単位で完全に同じ出力になる**（`md5sum` で確認済み）。
- 日付計算はすべて `ANCHOR_DATE = 2026-09-01` を基準にする。`datetime.now()` は使っていない
  （使うと実行日によって出力が変わり、上の「2回流して同じ」が壊れるため）。
- 依存パッケージは無い（Python標準ライブラリのみ）。5実装のどの言語からもこのJSONを
  そのまま読み込める。

スクリプトは生成のたびに自分で検算し、結果を標準出力に出す。**全項目 `[OK]` でないと
`exit code 1` で終了する。**

## 検算のために意図的に仕込んだもの

このデータは各実装の検算（会計の未算入処理・検査値の判定表示・予約の重複防止など）を
確かめるための材料。以下を意図的に混ぜてあり、`make_data.py` 実行時に自己検査で確認できる。

1. **単価未設定の料金項目が8件**（`price_items.json`）。うち8件とも
   `billing_details` から複数回参照され、**16枚の伝票**に単価未設定の明細行が乗っている
   （1枚だけに集中させていない）。「未設定の行を0円として合計に入れない」ことを確認できる
2. **検査値に基準の外にある値を含む**（`lab_test_items` 全体で範囲外111件・範囲内290件、
   両方が混在）。基準は `lab_items.json` の `reference_ranges` から
   `species`（患者の `species`。dog/cat以外は `other` 扱い）と
   `sex`（male/female。`unknown` は `any` 扱い）で引く
3. **体温・体重は患者ごとに違う値**。`progress_notes` の `temperature_c` と
   `visits`/`progress_notes` の `body_weight_kg` は、患者ごとに決めた基準値（種別に応じた
   体格・体温帯）に個体差の揺らぎを加えて生成している。全患者が同じ値になっていないことを
   自己検査で確認済み（ユニーク値が複数存在することを検査）
4. **予約は担当・処置室ともに重ならない**。時間帯を資源（担当者 or 処置室）ごとに管理しながら
   割り当てているため構造的に重複しないが、念のため生成後に総当たりで重複を検査している
5. **入院の記録行（`care_records`）は実施者(`performed_by_staff_id`)が必ず入っている**。空の行は0件
6. **削除済み（`deleted_at` あり）行を少数含む**（owners 2件・patients 2件・visits 2件）。
   一覧からは既定で隠れるが、件数集計には残る想定のデータ

自己検査は次を確認している（`make_data.py` の `run_self_checks`）。

- 予約の重複が0件
- 入院の記録行に実施者が空のものが0件
- 体温がすべて同じ値になっていない（ユニーク値 > 1）
- 体重がすべて同じ値になっていない（ユニーク値 > 1）
- 単価未設定の料金項目がちょうど8件
- 単価未設定の明細行が5枚以上の伝票にまたがっている
- 各伝票について、明細の「単価が設定されている行」の合計（数量×単価の和）と、
  confirmedの場合の `paid_amount` が一致する（**未算入の行は合計に含めない**）
- 削除済み（`deleted_at` あり）の owners / patients / visits がそれぞれ1件以上ある
- 検査値が範囲内・範囲外の両方を含む

## この生成データについての注意（実装側で踏まえてほしいこと）

- `Billing` に合計金額を保存するフィールドは無い（`spec/model.md` どおり）。
  合計は `billing_details` から都度計算する。`unit_price` が `None` の行は
  **金額に含めず、件数として別に示す**こと
- `seed.json` の `staff.password_hash` はダミー文字列のSHA-256ハッシュ値であり、
  実在するパスワードとは一切関係ない。ログイン機能を作る場合は各自の方式でよいが、
  平文のパスワードをこのファイルに追加しないこと
- `masters.json` は画面から編集しない前提の固定データ。読み込み専用として扱うこと
- `lab_items.json` の基準値は一般的な目安として作成した架空の数値であり、
  実在の検査機関・製品の基準値をそのまま転記したものではない
