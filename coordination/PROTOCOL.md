# 協調のルール — 5レーン並列

前回の並列開発（2026-09-04、3レーン）の `coordination/README.md` の不変条件を引き継ぎ、
**レーンが5つに増えることで悪化する点を補強**した版。

## 不変条件（破ると全体が壊れる）

1. **git を触るのは指揮役だけ。** レーンは commit / push / checkout をしない
2. **`spec/` と `tests/` は凍結。** 変更が要るときは全レーンを止めて指揮役が判断する
3. **所有ディレクトリの外を書かない。** 割当は `ASSIGNMENT.md` が唯一の正。
   **例外は2つだけ** — 自分の `coordination/status/lane-*.md` と `coordination/qa/lane-*.md`。
   この2つは「書け」と決めてあるので、所有ディレクトリの外だが書いてよい
   （書けないと進捗も質問も出せなくなる。レーンRの指摘 R-11）
4. **テストの期待値を実装に合わせて書き換えない。** 疑わしいときは `qa/` で質問する
5. **レーン同士で直接やり取りしない。** 契約は `spec/` だけであり、会話で決めた仕様は他レーンへ伝わらない

## レーンが増えることで足したもの

### 6. 起動文面はレーンごとに変える

前回の並列開発 で実際に起きた事故（`AI開発/前回の並列開発/coordination/ASSIGNMENT.md` に記録）:

> ユーザーは3つのCLIに**同一の起動文面**を貼った。そのため各CLIは自分のレーンを知らずに起動した

そこから、ロックファイルの自己申告を意図と誤読 → 割当が二転三転、という連鎖が起きた。
**レーンが5つになれば確実に悪化する。**

対策: `briefs/lane-a.md` 〜 `lane-e.md` を用意し、**1文目に必ずレーン名を書く**。
起動時はそのファイルを指定して貼る。**同じ文面を複数のCLIに貼らない。**

### 7. 自己申告で割当を決めない

ロックファイル・作業中のファイル・タイムスタンプから**割当を逆算しない**。
`ASSIGNMENT.md` だけが正である。矛盾を見つけたら、自分の作業は続けたまま指揮役へ報告する。

### 8. 指揮役は「緑になった」を自分で確かめる

レーンが5つあると、指揮役が全部を読むのは無理になる。
だから**判定を自動化し、指揮役は落ちたものだけを見る**。

- レーンの完了報告は**引き金にすぎない**。指揮役が共通テストを自分で走らせて判定する
- 5レーン分を目視で読もうとしない。読むのは**テストが落ちたところと、テストに無い振る舞い**だけ

### 9. 質問は止まるかどうかで経路を分ける

| 状況 | 経路 |
| --- | --- |
| 答えが無いと**実装が止まる** | 指揮役へ直接メッセージ（`SendMessage`） |
| 止まらない | `qa/lane-*.md` に書いて**先へ進む**。指揮役が後で答える |

**待たない。** 5レーンが指揮役の返事待ちで止まると、並列にした意味が消える。
止まらない質問は、自分で仮決めして進み、**仮決めしたことを `qa/` に書く**。

### 10. 状況は `status/` に書く

指揮役は `status/` と共通テストの結果で全体を把握する。
**指揮役から進捗を聞かれる前に書く。** 聞く手間が5倍になるため。

## ディレクトリ

| 場所 | 用途 |
| --- | --- |
| `briefs/` | 各レーンへ渡す指示書。**レーンごとに別ファイル** |
| `qa/` | レーン→指揮役の質問と、指揮役→レーンの回答 |
| `status/` | 各レーンの進捗 |
| `spec/` | 契約（凍結）。**指揮役だけが触る** |
| `tests/` | 共通テスト（凍結）。**指揮役だけが触る** |
