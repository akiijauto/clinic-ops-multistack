# 先に決めてあること — 指揮役がオーナーへ聞かずに進めるための土台

**この文書の目的は、実装中にオーナーへの質問が発生しないようにすること。**

指揮役が判断に迷ったら、まずここを読む。**ここに書いてあることは決定済みであり、
蒸し返さない。** ここに無い事柄の扱いは末尾の「ここに無いことが出たら」に従う。

## 2. インストールと依存

| 論点 | 決定 |
| --- | --- |
| 新しい実行環境（言語・ランタイム）の導入 | **禁止。** 必要になったら中止条件に該当するので止めて報告する |
| プロジェクト内の依存追加 | **許可済み。**`go get` / `bundle install` / `npm install` / `composer require` / `pip install` を、このリポジトリの中に閉じて行ってよい |
| 依存の追加後 | **必ず整合を取る**（`go mod tidy` 等）。「依存を足した」と「ビルドに必要なものが揃った」は別 |
| 脆弱性勧告で止まったとき | **勧告を読み、修正版があればそれを使う。** 無ければ止めて報告する（2026-09-05 に php-jwt で実際に起きた。7.0.0 で修正済みだった） |

## 4. 仕様の判断（レーンから質問が来たときの答え）

**契約（`spec/`）に書いてあることが正。** 書いていないことは、下記の原則で指揮役が決める。
**オーナーには聞かない。**

| 迷いどころ | 決め方 |
| --- | --- |
| 画面の見た目 | **各スタックの流儀で書いてよい。** 揃えるのは振る舞いだけ |
| エラーの文言 | **`spec/openapi.yaml` に書いてあるものを一字一句使う。** 独自の文言を作らない |
| 数値の丸め | **`spec/acceptance.md` の規則に従う。** 書いていなければ**丸めない**（切り捨て・四捨五入を勝手に入れない） |
| 日付・時刻の境界 | **JST で扱う。** 集計の月境界も JST（この業務は国内の窓口業務なので） |
| 文字数の数え方 | **文字数で数える。** バイト数で数えない（日本語で3倍になる） |
| 未入力の扱い | **「0として集計する」ことを禁止する。** 未算入の件数を明示する（実システムで実際に出た不具合） |
| DBの選択 | **各レーンが選んでよい。** ただし**追加インストールが要らないもの**に限る（SQLite を推奨） |
| 認証 | **この計画では扱わない。** 画面はログイン済みの前提で作る |

## 5. 品質の基準（完了の判定）

レーンが「終わった」と言えるのは、次のすべてを満たしたときだけ。

1. **共通テスト（`tests/`）が緑**。自分で書いたテストが緑でも完了ではない
2. `spec/acceptance.md` の**検算がすべて一致**する
3. **テストの期待値を実装に合わせて書き換えていない**（疑わしければ `qa/` で質問する）
4. 秘密情報・実データ・参照元が分かる記述が入っていない

**指揮役は「緑になった」という自己申告ではなく、自分で共通テストを走らせて確認する。**

---

## 6. ここに無いことが出たら

指揮役は次の順で判断する。**オーナーへ聞くのは最後の手段**で、原則として起きない想定。

1. **`spec/` に答えがあるか**を見る。あればそれに従う
2. **無ければ、上の第4節の原則から導けるか**を考える。導けるなら決めて `qa/` に記録する
3. **導けない場合、それは契約の欠陥**である。全レーンを止めて指揮役が契約を直し、
   変更を `qa/` へ通知してから再開する
4. **中止条件（`PLAN.md`）に当たる場合だけ**、止めてオーナーへ報告する

**「念のため聞いておく」はしない。** 判断を委ねられている範囲で決めて、記録を残す。
決めた内容が後で間違いと分かったら、そのときに直せばよい。
止まっている時間のほうが高くつく。
