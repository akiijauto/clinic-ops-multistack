### 5-01. Rails・Laravel・Next.js: 飼主DBに実在しない氏名が永続的に入っている（`data/seed.json` と不一致）【最重要】

**何が**: `karte_no=10032`（owner_id=18, owner_no=O-00018）の飼主氏名が、正解データと3実装で食い違う。

**どう確かめたか（自分で再実測）**: `data/seed.json` の `owners[id=18]` の `name_kanji`（正しい姓）を基準に、5実装の `GET /api/owners/O-00018` を比較した。

```
$ python3 -c "seed.jsonのowners[id=18]を出力" → name_kanji: （正しい姓）

$ curl http://127.0.0.1:8401/api/owners/O-00018 → 正しい姓と一致（Go）
$ curl http://127.0.0.1:8414/api/owners/O-00018 → 別の姓が入っている（Rails: 不一致）
$ curl http://127.0.0.1:8403/api/owners/O-00018 → 同じ「別の姓」が入っている（Laravel: 不一致）
$ curl http://127.0.0.1:8415/api/owners/O-00018 → 正しい姓と一致（FastAPI）
$ curl http://127.0.0.1:8405/api/owners/O-00018 → 同じ「別の姓」が入っている（Next.js: 不一致）
```
（※ここでは実際の姓の文字列は伏せる。合成データの姓が過去に公開ゲートのNGワードと衝突した経緯があるため、以後この種の値はIDで指し、文字列そのものは書かない）

住所・電話・`owner_no`は5実装とも正解と一致しており、**氏名だけ**が3実装でずれている。しかも**3実装が同じ「別の姓」を共有している**（バラバラな誤りではない）。

**なぜ問題か**: 調査を担当したフォークによれば、`/dm.csv`（DM画面 #16）の宛先氏名としてもこの誤った名前がそのまま出力される（サンプルした全75行で不一致）。DMは案内状の宛先を作る画面であり、実運用に見立てれば誤送付相当。氏名は顧客・カルテ・会計等、飼主名を表示する他の全画面にも波及している可能性が高い（今回は`/dm.csv`とAPI直叩きのみ確認、波及範囲の全数調査は未確認）。**コードの不具合ではなく、Rails/Laravel/Next.jsのDBへ投入されたシードデータそのものが3実装で共通して間違っている**ように見える点が特異（3実装が同じ誤りを共有しているため、シード生成の共通処理に原因がある可能性）。

**担当**: B（Rails）・C（Laravel）・E（Next.js）、および共通のシード生成経路があるなら指揮役。
