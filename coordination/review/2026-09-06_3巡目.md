に書き換わっており、`make_briefs.py` の生成元も同じ内容。**本当に直っています。**

**R-05（`--allowedTools` の語分割）**: `scripts/launch-lanes.sh` は
`read -r -a tools <<< "$COMMON_TOOLS ${LANE_TOOLS[$l]}"` という形に変わりましたが、
**この `read -a` 自体が空白で区切ります。** 実際に切り出して確かめました。

```
$ read -r -a tools <<< "... Bash(go *) Bash(gofmt *)"
$ echo ${#tools[@]}                     # → 15（本来は Edit/Write/... の7つ + LANE_TOOLS の2つ = 9であるべき）
[12] <Bash(go>      ← Bash(go *) がまだ2つに割れている
[13] <*)>
[14] <Bash(gofmt>
[15] <*)>
```

**「`bash -n` と DRY_RUN で確認済み」という報告について**: `bash -n` は構文チェックしかせず、
この種の壊れ方は検出できません。DRY_RUN の出力を見ると:

```
printf '  [DRY_RUN] session-id=%s tools=%s\n' "${SESSION_ID[$l]}" "${tools[*]}"
```

`${tools[*]}` は配列を**もう一度空白で連結して**表示するので、割れた配列を見ても
壊れる前の文字列と**見分けが付きません**。**確認の方法自体が、この不具合を隠す形になっています。**

`--allowedTools` へは最終的に `"${tools[@]}"` と正しく展開して渡っているので、
`Edit` `Write` `Read` 等の**空白を含まない項目**は問題なく届きます。
実害があるのは `Bash(go *)` のように**1項目の中に空白がある**もの
（各レーンのスタック固有の道具と、レーンRの `git worktree *` 等）だけです。

**担当**: 指揮役。直し方は1巡目の提案のとおり
（`LANE_TOOLS` を配列そのもので持つ。例: `LANE_TOOLS_A=("Bash(go *)" "Bash(gofmt *)")`）。
DRY_RUNで確認するときは `${tools[*]}` ではなく `declare -p tools` で**要素数と各要素の中身**を見ること。
